01

Why a menu or a VA does not solve this

  • The showroom is open Monday to Friday, 10am to 5pm. 9 in 10 calls arrive outside that window, including $40,000 inquiries at 11pm and on Sundays. They were hitting a voicemail box nobody actioned before Monday.
  • They hired a virtual assistant first. A VA without inventory access cannot answer the only question that matters: do you have this piece, and what does it cost.
  • The catalog changes daily, so a static export is wrong within 24 hours. Any answer has to come from live data.
  • Speech-to-text mangles the brand names. Jaeger-LeCoultre, Audemars Piguet, Breguet. Model numbers mix digits, letters and punctuation, carry a Preowned- prefix on some products only, and around 100 products are near-duplicates of each other.

02

How it works

6 n8n workflows in 3 layers: keep the data current, answer the lookup, write the result back.

Layer 1  Catalog and order sync

n8n’s Shopify node returns 50 records per call, and looping it hard enough to finish a full pull kept tripping rate limits and deactivating the workflow. I replaced it with a custom HTTP request walking the page_info cursor at roughly 250 records per iteration: 5x the throughput, stable unattended. It PATCHes into Airtable rather than creating, so a price change updates in place instead of duplicating the record.

Layer 2  Lookup, ranking and disambiguation

3 lookup workflows sit behind webhooks registered as agent tools. Each runs the same shape: extract the argument from the tool call, normalize it, query Airtable, rank the candidates, format the winner for speech.

  • 1Product nameLong and brand-heavy. This is what callers mispronounce and what speech-to-text mangles.
  • 2PriceThe tiebreaker. When a name hits a cluster of near-identical pieces, price separates them.
  • 3Model numberDigits, letters, dots, and a Preowned- prefix only some products carry.

Ambiguity resolves by asking, not guessing. When a model-number match returns more than one candidate, the agent requests the price or product name and narrows to one. A pronunciation dictionary in the agent fixes brand and model strings before they ever reach the workflow, because none of the matching helps if the input is already wrong.

Layer 3  Writeback and reporting

Every completed call writes transcript, recording, caller and a link to the exact product asked about into Airtable. A scheduled workflow assembles overnight activity and emails it before the shop opens, because the owner was never going to open a dashboard.

04

Three failures that never showed in the metrics

Found by listening to real calls every week, not by reading the success rate.

  • A broken email domain. The agent read the contact address as “world of luxurious dot com”. Every caller routed to email got an address that does not exist, and every one of those calls logged as successful.
  • Lead capture asked too late. Callers answered 3 or 4 product questions, then hung up the moment the agent asked for a name.
  • No recovery from a misheard name. One caller’s name came through as “12”. The agent had no path back and the call timed out, losing a $21,000 inquiry at the final step.
